# 🗄️ Supabase — база даних Ashlands

Тут лежить усе, що стосується бази даних: SQL-скрипти для створення таблиць та інструкції.

Гра працює у двох режимах:
- **є ключі в `.env`** — дані зберігаються в Supabase;
- **нема ключів** — дані зберігаються у файли в папці `data/` (зручно для тестів без інтернету).

---

## 📁 Що тут лежить

| Файл | Що робить |
|---|---|
| `all.sql` | **Створює всю базу одним запуском.** Безпечно запускати повторно |
| `migrations/001_users.sql` | Таблиця акаунтів |
| `migrations/002_sessions.sql` | Таблиця входів |
| `migrations/003_admissions.sql` | Хто з гравців допущений у гру |
| `migrations/004_meta.sql` | Службова інформація сервера |
| `migrations/005_characters.sql` | Персонажі гравців + сховище аватарок (bucket `avatars`) |
| `migrations/006_character_positions.sql` | Де стоїть персонаж на карті |
| `migrations/007_display_name.sql` | Ім'я або нік гравця |
| `migrations/008_sheet_items_inventory.sql` | Лист і золото персонажа, бібліотека предметів, інвентар, bucket `items` |
| `migrations/009_world.sql` | Світ: локації (міста, підземелля) і дороги |
| `migrations/010_travel.sql` | Подорожі: маршрут і стан руху персонажа |
| `migrations/011_groups.sql` | Групи гравців |
| `migrations/012_dm_tools.sql` | Нотатки ДМ, перебування в катакомбах |
| `migrations/013_city_scenes.sql` | 3D-сцени міст (будівельник) |
| `migrations/014_city_terrains.sql` | Земля 3D-міст з точок (будівельник) |
| `reset.sql` | ⚠️ Стирає **всі** дані (таблиці лишаються). Перед справжньою грою |

`all.sql` — це всі файли з `migrations/` разом. Коли додаємо нову частину гри (персонажі, предмети, карта), з'являється новий файл `migrations/005_...sql`, і він же дописується в кінець `all.sql`.

## 🚀 Перше підключення

### 1. Створити таблиці
1. Відкрий свій проєкт на https://supabase.com/dashboard.
2. Ліве меню → **SQL Editor** → **New query**.
3. Скопіюй увесь вміст файлу `all.sql`, встав і натисни **Run**.
4. Має з'явитися `Success. No rows returned`.
5. Ліве меню → **Table Editor**: маєш побачити таблиці `users`, `sessions`, `admissions`, `app_meta`, `characters`.
6. Ліве меню → **Storage**: має з'явитися bucket `avatars`.

### Якщо база вже створена, а з'явилась нова міграція
Запусти **тільки новий файл** з `migrations/` (наприклад, `005_characters.sql`) так само через SQL Editor → Run. Або весь `all.sql`: він безпечний для повторного запуску.

### 2. Взяти ключі
1. Ліве меню → ⚙️ **Project Settings**.
2. **Data API** → скопіюй **Project URL** (виглядає як `https://abcd1234.supabase.co`).
3. **API Keys** → розділ **Secret keys** → скопіюй ключ `sb_secret_...`.
   - Якщо там порожньо, натисни **Create secret key**.
   - Старі проєкти: вкладка **Legacy API Keys** → ключ `service_role`.

> ⚠️ **Секретний ключ дає повний доступ до бази.** Не надсилай його нікому, не вставляй у чат і не викладай на GitHub.

### 3. Вписати ключі в гру
1. У корені проєкту скопіюй файл `.env.example` і назви копію `.env`.
2. Впиши свої значення:
   ```
   SUPABASE_URL=https://abcd1234.supabase.co
   SUPABASE_SECRET_KEY=sb_secret_...
   ```
3. Файл `.env` автоматично **не потрапляє в git**.

### 4. Запустити
```bash
npm run dev
```
У терміналі має бути: `Ashlands запущено: http://localhost:3000 (дані: Supabase)`.

Якщо таблиць нема, сервер напише, що треба запустити `all.sql`.

## 🔒 Безпека

- На всіх таблицях увімкнено **RLS** (Row Level Security) без жодних правил. Тобто ззовні, з публічним ключем, **ніхто не може ні прочитати, ні змінити** дані.
- Працює з базою **тільки сервер гри** через секретний ключ.
- Паролі в таблиці `users` зашифровані (scrypt), справжній пароль ніде не зберігається.
- Сесії зберігаються як хеш токена: навіть якщо хтось побачить таблицю, увійти за чужого не вийде.

---

## 🧹 Очистити тестові дані

Перед справжньою грою:
1. **Зупини сервер** (`Ctrl+C`).
2. Supabase → **SQL Editor** → встав вміст `reset.sql` → **Run**.
3. Запусти сервер, зареєструй акаунти ДМ і видай роль: `npm run make-dm <логін>`.

## 📊 Таблиці

### `users` — акаунти
| Колонка | Що це |
|---|---|
| `id` | унікальний id |
| `login` | логін (унікальний без урахування регістру), лише для входу |
| `display_name` | ім'я або нік, яке бачать інші (2–30 символів, може повторюватись) |
| `password_hash` | зашифрований пароль |
| `role` | `player` або `dm` |
| `dm_note` | примітка ДМ про гравця (до 200 символів) |
| `first_admitted_at` | коли ДМ вперше пустив (порожньо = «Новий») |
| `active_character_id` | вибраний персонаж |
| `created_at` | коли зареєструвався |

### `sessions` — входи
| Колонка | Що це |
|---|---|
| `token_hash` | хеш токена входу |
| `user_id` | чий вхід |
| `created_at` | коли увійшов |

### `admissions` — допуск у гру
| Колонка | Що це |
|---|---|
| `user_id` | хто допущений |
| `admitted_at` | коли ДМ пустив |
| `away_since` | з якого моменту відсутній (порожньо = онлайн) |

### `characters` — персонажі
| Колонка | Що це |
|---|---|
| `id` | унікальний id |
| `user_id` | чий персонаж |
| `name` | ім'я (2–40 символів) |
| `avatar_path` | шлях до картинки в bucket `avatars` (порожньо = без аватарки) |
| `status` | `pending` (чекає ДМ), `approved` (підтверджений), `rejected` (відхилений) |
| `pos_x`, `pos_y` | де стоїть на карті світу (пікселі карти; порожньо = ще не на карті) |
| `sheet` | лист персонажа (JSON: клас, рівень, характеристики…) |
| `gold` | золото |
| `travel` | подорож (JSON: маршрут, тривалість, скільки пройдено, пауза); порожньо — стоїть |
| `dungeon` | у катакомбах (JSON: підземелля, вхід, таймер, пауза, спосіб виходу); порожньо — на карті |
| `created_at` | коли створений |
| `reviewed_at` | коли ДМ вирішив |

### `items` — бібліотека предметів (створює ДМ)
| Колонка | Що це |
|---|---|
| `id` | унікальний id |
| `name` | назва (2–60) |
| `kind` | `common` — звичайний (стопка), `special` — особливий (кожен окремо) |
| `description` | опис |
| `stats` | характеристики |
| `image_path` | картинка в bucket `items` |

### `inventory` — інвентар
| Колонка | Що це |
|---|---|
| `id` | запис |
| `character_id` | чий |
| `item_id` | який предмет з бібліотеки |
| `quantity` | кількість (для особливих завжди 1) |
| `custom_stats` | свої характеристики цієї копії особливого предмета (порожньо = як у бібліотеці) |

### Storage → `items` — картинки предметів
Як і `avatars`: публічне читання, завантажує лише сервер, до 512 КБ.

### Storage → `avatars` — картинки аватарок
Публічне читання (щоб гравці бачили аватарки), завантажує лише сервер. До 512 КБ, лише WebP / PNG / JPEG.

### `locations` — міста й підземелля
| Колонка | Що це |
|---|---|
| `id` | унікальний id |
| `type` | `city` (місто) або `dungeon` (підземелля) |
| `name` | назва (2–60) |
| `description` | опис для гравців |
| `x`, `y` | де на карті (пікселі карти) |

### `roads` — дороги
| Колонка | Що це |
|---|---|
| `id` | унікальний id |
| `from_id`, `to_id` | які дві локації з'єднує |
| `points` | точки згину між ними: `[[x, y], ...]` |

### `groups` — групи
| Колонка | Що це |
|---|---|
| `id` | унікальний id |
| `leader_character_id` | лідер (персонаж) |
| `members` | учасники: `[{ characterId, joinedAt }]` |

Запрошення й голосування живуть лише в пам'яті сервера (короткі, по 2 хв).

### `dm_notes` — нотатки ДМ
| Колонка | Що це |
|---|---|
| `id` | унікальний id |
| `title` | назва (до 100) |
| `body` | текст (до 10 000) |

Кидки кубиків живуть лише в пам'яті сервера (останні 30).

### `city_scenes` — 3D-сцени міст
| Колонка | Що це |
|---|---|
| `location_id` | місто |
| `folder` | папка моделей міста (`client/assets/models/cities/<folder>`), порожньо — лише спільні |
| `objects` | що стоїть: `[{ id, model, x, y, z, rotY, scale }]` (метри від центру міста) |

### `app_meta` — службова інформація
| Колонка | Що це |
|---|---|
| `key` | `server` — запуски сервера; `world` — стартова точка, «рух з дозволом», пауза гри, годинник |
| `value` | дані (кількість запусків тощо) |
